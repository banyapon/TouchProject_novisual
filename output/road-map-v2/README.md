# ผังถนน v2

- `road_map_v2_512.png`: ภาพอ้างอิง 512×512 เส้นขาวบนพื้นดำ
- `road_map_v2.svg`: ภาพเดียวกันแบบเวกเตอร์ ซูมอ่านเลขได้
- `road_data_v2.json`: ข้อมูลถนนและพิกัดที่ใช้วาดภาพอ้างอิง
- `road_ids.csv`: ตาราง ID และปลายทางของเส้นเชื่อม
- `validation.json`: ผลตรวจความเชื่อมต่อของข้อมูล

## รูปแบบถนน

วงนอกและวงในเป็นสี่เหลี่ยม แกนกลางเป็น + แนวตั้ง–แนวนอน ไม่มีถนนเส้นทแยงมุม เส้นเชื่อมสำหรับเลี้ยวเป็นเส้นโค้งสั้น ๆ ที่ทางแยก

ถนนหลัก 16 เส้น (ID 1–16) และเส้นเลี้ยว 56 เส้น (ID 17–72) รวม 72 เส้น เลขคู่บนภาพ เช่น `17/18` หมายถึงถนนสอง ID แยกขาไปและขากลับ ไม่ใช่ ID เดียว

| ID | ตำแหน่ง |
|---|---|
| 1 / 2 / 3 / 4 | เชื่อมวงนอกกับวงใน ด้านตะวันตก / ตะวันออก / เหนือ / ใต้ |
| 5 / 6 / 7 / 8 | แขน + ตรงกลาง ด้านตะวันตก / ตะวันออก / เหนือ / ใต้ |
| 9–12 | วงใน เริ่มมุมตะวันตกเฉียงเหนือ วนตามเข็มนาฬิกา |
| 13–16 | วงนอก เริ่มมุมตะวันตกเฉียงเหนือ วนตามเข็มนาฬิกา |
| 17–24 | เส้นเลี้ยวแยกกลาง |
| 25–32 / 33–40 / 41–48 / 49–56 | เส้นเลี้ยวแยกวงใน ตะวันตก / เหนือ / ตะวันออก / ใต้ |
| 57–60 / 61–64 / 65–68 / 69–72 | เส้นเลี้ยวสามแยกวงนอก ตะวันตก / เหนือ / ตะวันออก / ใต้ |

ตรงไปที่แยกเชื่อมใน `nodeS/nodeE` โดยตรง ไม่เพิ่ม road ID อีกเส้น ช่วงตรงสั้น ๆ ระหว่างปากแยกเก็บพิกัดไว้ใน `junctions[].straightConnections` เพื่อให้ตำแหน่งเคลื่อนที่ต่อเนื่อง มุมสี่เหลี่ยมที่ไม่มีทางเลือกเป็นส่วนหนึ่งของถนนหลักรูปตัว L ไม่เพิ่ม ID เส้นเลี้ยว

## ความหมาย 0 / 1 และขากลับ

- `nodeS` = ปลาย 0; `nodeE` = ปลาย 1
- `enterNode` = ปลายของ **ถนนปลายทาง** ที่จะเข้า
- `direction: -1` = ถนนหลัก วิ่งได้สองทิศทาง
- `direction: 0` = เส้นเลี้ยวขาไป วิ่ง S→E เท่านั้น และเข้าได้ที่ `allowedEntryNodes: [0]`
- `direction: 1` = เส้นเลี้ยวขากลับ วิ่ง E→S เท่านั้น และเข้าได้ที่ `allowedEntryNodes: [1]`
- `reverseRoad` = ID คู่ขากลับ

ทั้งคู่เก็บจุด S/E ในลำดับเดียวกัน แต่เส้นขากลับใช้ทิศทางตรงข้ามและมีโค้งแยกในภาพ จึงไม่ต้องใช้ถนน ID เดิมย้อนกลับ

**ข้อแตกต่างที่ต้องระวัง:** 1→0 / 0→1 บอกคู่ปลายถนนที่เชื่อมกัน ไม่ใช่ชื่อทิศทางเดินทางเสมอไป เมื่อมีหลายแขนที่แยก บางคู่ต่อ S–S หรือ E–E จึงเป็น 0→0 หรือ 1→1 ตามจริง การบังคับให้ทุกคู่เป็น 1→0 จะทำให้กราฟไม่ตรงตำแหน่ง ตัวอย่างขาไป ID 17 เชื่อมถนน 5 ปลาย E ไปถนน 7 ปลาย E; ขากลับ ID 18 เชื่อมกลับจากถนน 7 ไปถนน 5

ตัวอย่างเส้นเลี้ยวแยกกลาง:

```text
5.nodeE -> 17.nodeS -> 17.nodeE -> 7.nodeE     (ขาไป ใช้ ID 17)
7.nodeE -> 18.nodeE -> 18.nodeS -> 5.nodeE     (ขากลับ ใช้ ID 18)
5.nodeE -> 6.nodeS                           (ตรงไป ไม่เพิ่ม ID)
6.nodeS -> 5.nodeE                           (ตรงกลับ ไม่เพิ่ม ID)
```

`nodeS/nodeE` เก็บการเชื่อมต่อทางกายภาพแบบไป–กลับให้ตรวจ reciprocal ได้ ก่อนเลือกทาง ต้องกรองให้ `connection.enterNode` อยู่ใน `allowedEntryNodes` ของถนนปลายทาง ไม่เช่นนั้นจะเลือกขากลับผิด ID ค่าทางออกเริ่มต้นเลือกตรงไปถ้ามีทางตรง

## การใช้กับ Unity

ชุดนี้เป็นแบบและข้อมูลใหม่แยกใน `output/road-map-v2` ยังไม่ได้ติดตั้งแทนแผนที่ในฉากหรือแก้โค้ดเกม

ตัวอ่านเดิมใน `RoadNetworkSplineCreator.cs` ตรวจจำนวนถนนกับชุด spline ที่กำหนดไว้ และยังไม่อ่าน `direction`, `allowedEntryNodes`, `points` หรือ `straightConnections` จึงไม่สามารถเปลี่ยนชื่อ JSON แล้วใช้แทนไฟล์เดิมได้ทันที การนำเข้าแบบใหม่นี้ต้องสร้าง spline จาก `points`, รองรับข้อจำกัดทิศทาง และเคลื่อนข้ามช่วงต่อทางตรงด้วยพิกัด `straightConnections`

## การตรวจและที่มาภาพ

รัน `python output/road-map-v2/build_map.py` เพื่อสร้าง JSON, SVG, CSV และตรวจ ID ไม่ซ้ำ, ปลายเชื่อมกลับได้, พิกัดปลายโค้งตรงกับถนนหลัก, ขาไป–กลับมีคู่ครบ, ไม่มีถนนหลักทแยง, มีทางออกที่ถูกต้องเพียงหนึ่งทางต่อแขน และเดินทางได้ทั่วกราฟทั้ง 88 สถานะทิศทาง

ภาพร่าง `imagegen_preview.png` สร้างด้วย built-in image_gen จากภาพที่ผู้ใช้ให้และคำสั่งใน `imagegen_prompt.txt` ภาพอ้างอิงสุดท้าย `road_map_v2.svg` และ PNG เรนเดอร์จากข้อมูลพิกัดเดียวกับ JSON เพื่อให้ ID และตำแหน่งเส้นเชื่อมตรงกันแน่นอน ใช้ภาพอ้างอิงสุดท้ายสำหรับตรวจข้อมูล
